Instalar dependencias de desenvolvimento:
    python -m venv .venv
    .venv\Scripts\pip install -r requirements-dev.txt

Rodar os testes:
    .venv\Scripts\python -m pytest

Gerar o executavel (saida em dist\):
    .venv\Scripts\pyinstaller --noconfirm Retalhos.spec    -> dist\Retalhos\Retalhos.exe

Gerar app + instalador:
    ferramentas\gerar_instalador.bat
    -> dist\instalador\Retalhos_Setup_<versao>.exe   (a versao vem de retalhos\__init__.py)
    Requer Inno Setup 6:  winget install JRSoftware.InnoSetup

Instalador (instalador\Retalhos.iss):
    - instala por usuario em %LOCALAPPDATA%\Programs\Retalhos, sem pedir administrador
    - mesmo AppId do instalador antigo: atualiza a instalacao existente
    - nao sobrescreve o Settings.json da maquina; maquina nova recebe instalador\Settings.padrao.json
    - nao apaga as planilhas (docs\, sheet_proj\), nem ao desinstalar
    - avisa se faltar o driver do Access 64 bits
    - com /REABRIR (usado pelo app ao se atualizar) abre o Retalhos de novo no fim

Publicar uma versao nova (as maquinas sao avisadas sozinhas):
    1. Suba a versao em retalhos\__init__.py (e pyproject.toml), ex.: 2.1.0 -> 2.2.0
    2. Escreva o que mudou em instalador\novidades.md (o usuario ve esse texto ao atualizar)
    3. Commit e push do codigo
    4. ferramentas\publicar_versao.bat
       - gera o instalador e o versao.json
       - cria a Release v<versao> no repositorio PUBLICO de instaladores (RepoAtualizacao do Settings.json,
         padrao EliveltonZ/Retalhos-Releases). O codigo continua no repositorio privado.
       - copia instalador + versao.json para a pasta do local_zip (\\GDD02\sistema\Developer)
       Opcoes: --sem-build (usa o instalador ja gerado), --so-rede, --so-internet
    Requer GitHub CLI logado na conta dona do repositorio:
       winget install GitHub.cli
       gh auth login
